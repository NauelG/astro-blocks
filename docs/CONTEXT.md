# CONTEXT.md — astro-blocks

Working context for humans and agents: the mental model of the system, the domain
vocabulary, the conventions we hold ourselves to, and the known traps ("gotchas").

Architectural **decisions** (the "why we chose X") live in `DECISIONS.md` (ADR-001…006)
and `adr/` (ADR-0007…0020, draft). The panel **design system** lives in `DESIGN.md`. The
working **cycle and policies** live in `AGENTS.md`. This file is the **operational** companion:
what things are called, how we do things, and where the sharp edges are.

---

## 1. Mental model

`@astroblocks/astro-blocks` is an **Astro integration** (npm package, BUSL-1.1) that adds a
file-backed CMS to a consumer's Astro site. There is no database — all content is JSON on disk.

```
              ┌─────────────────────────── plugin/index.ts (the integration) ───────────────────────────┐
consumer      │  astro:config:setup  → validate options.blocks / options.globalBlocks, inject routes,     │
```

> Paths in the diagram above are relative to **`src/`** (`plugin/index.ts` → `src/plugin/index.ts`).
> They name modules, not filesystem locations — see the publish-root convention in §4.

- **Two block systems**: *page-scoped blocks* (`blocks[]`, per-page content) and *global blocks*
  (`globalBlocks[]`, edit-once/reference-anywhere: header/footer/sections). Global blocks reuse
  `BlockInstance[]` + `LocalizedValueMap`, so i18n is free. (obs #132)
- **`src/api/handlers.ts` is a thin NodeNext re-export shim**; real logic lives in `src/api/handlers/*.ts`
  domain modules. Do not expect logic — or line numbers — in `handlers.ts`. (ADR-0012, obs #1996)
- **`src/routes/admin/client/block-form.ts` is the single source of truth for block field rendering**,
  used by both the page editor and the global-blocks editor via `mountBlockForm`. Change field
  rendering there, not per-editor. (obs #138)
- **Data layer is `src/api/data.ts`**: every store (pages, menus, media, …) goes through an atomic
  `writeJson` (tmp file + `fs.rename`) and a per-path promise-chain mutex `withFileLock`. (ADR-0008, obs #805)

## 2. Routing & prefixes

- **Admin panel** — everything under **`/cms`**: `/cms`, `/cms/pages`, `/cms/redirects`,
  `/cms/configs`, `/cms/users`, `/cms/settings`, `/cms/menus`, `/cms/languages`, `/cms/cache`.
  Create/edit (detail) happens in a **modal on the list page itself** — there are no `/new` or
  `/[id]` routes.
- **API** — under **`/cms/api`**: `pages`, `pages/[id]`, `site`, `menus`, `redirects`, `configs`,
  `languages`, `users`, `upload`, `cache/invalidate`.
- **Site pages** — injected route **`/[...slug]`**. In alpha, SSR by default with Astro's
  experimental cache (`src/routes/page.astro`); if the consumer forces `publicRendering: 'static'`, the
  plugin injects `src/routes/page-static.astro`. Home = empty slug or `/`.
- **Sitemap / robots** — `/sitemap-index.xml`, `/robots.txt` (endpoints with `prerender = false`).
- When adding panel or API routes, keep these prefixes and update links and `fetch()` in the admin
  `.astro`. Changing the prefix = search/replace `/cms` and `/cms/api` across plugin, admin,
  `robots-get.ts` and README, and adjust `getPathSegments` in the catchall (e.g. `slice(2)`).

## 3. Glossary (domain vocabulary)

| Term | Meaning |
|---|---|
| **Block** | A typed content unit `BlockInstance { type, props }` rendered by a consumer-provided schema + `.astro` component. Two flavors: page-scoped and global. |
| **Global block** | A reusable block edited once and referenced from pages/layouts (header, footer, CTA). Declared via `globalBlocks: [{ slug, label }]`. (obs #132) |
| **Registry / runtime.mjs** | The generated `.astro-blocks/runtime.mjs` (gitignored): component map, schema map and global-block registry. It **imports the consumer's real `.astro` components**, so it can only be loaded inside a Vite graph — Astro pages reach it through the `astro-blocks-runtime` alias (ADR-0009). Its data twin is the **Schema map**. |
| **Schema map** | The block schemas, keyed by block type — the answer to *"is this prop localizable? is it an image?"*. Emitted **twice**: inside `runtime.mjs` (for the alias), and alone as pure data in `.astro-blocks/schema-map.mjs`. That second file exists for exactly one reason: it can be `import`ed from plain Node, which `runtime.mjs` cannot. Both are gitignored build artifacts. |
| **Bake** | Passing a value to the **precompiled API route** by splicing it into the bundle at config time via `vite.define` → `import.meta.env.*`. That route is not part of the consumer's Vite graph, so it cannot use the alias; and `.astro-blocks/` is gitignored, so it is routinely **absent** on a deployed server. Every registry the API route needs is therefore baked — the schema map and the global-block registry both. **The filesystem is a dev/test seam, never a resolution strategy** (ADR-0009, ADR-0025 — its absence is what #101 was). Baked values are **double-encoded** (`JSON.stringify` twice): `vite.define` splices raw *source*, so a single stringify emits a literal that `typeof === 'string'` guards reject. |
| **`LocalizedValueMap`** | A per-locale value map, e.g. `{ en: 'Hello', es: 'Hola' }`. A value is "localized" **only if every top-level key is a known locale code** (`isLocalizedMapValue`). (obs #813, #147) |
| **`ImageFieldValue`** | The structured image field value `{ url, alt?, width?, height?, caption? }` — replaced the old bare URL string. Its non-locale keys mean it passes through the localization layer untouched. (ADR-0016, obs #813) |
| **`MediaEntry`** | A row in `data/media.json` describing an uploaded asset (url, mime, variants, default alt, …). Caption is **not** stored here — it is per-component (ADR-0016). |
| **Variant** | A responsive size generated by sharp on upload; generation status is tracked in the media registry. (ADR-0017, obs #827) |
| **File-type catalog** | The closed table of file types the system **can handle** (`utils/file-catalog.ts`). One row = `{ mime, ext, contentType, category, disposition, raster }`. The stored extension, the served `Content-Type`, the inline/attachment policy, the sharp routing and the admin tile are all **derived from it** — no component keeps a private MIME map. (ADR-0023) |
| **Allowlist vs catalog** | `allowedFileTypes` is what is **switched on**; the catalog is what the system **can do**. Different questions. `allowedFileTypes` *selects* from the catalog and cannot widen it — a MIME with no row **fails the build**. Conflating the two is what produced the `video/mp4` 415. (ADR-0023) |
| **File category** | `'image' \| 'video' \| 'audio' \| 'document'` — a closed enum, **declared on the catalog row**, never parsed out of the MIME string. It governs the ingest strategy (buffer vs stream), the sharp routing, the serving policy and the media tile. (ADR-0023) |
| **Registered file type** | A type added by the consumer via `customFileTypes`. A *registration*, not a bypass: the denylist still applies, and it is **always** served `application/octet-stream` + `attachment`, so an unaudited format can never render in the CMS's own origin. (ADR-0023) |
| **Media surface vocabulary** | How the admin UI names uploads, by surface (ADR-0026, #114). **"Media"** = mass noun for the section/action (*Media*, *Choose media*). **"asset"** = the countable library item (*3 assets*; ES *recurso*). **"file"** = the disk action **and** the developer contract (dropzone, *Choose file*, the `file` prop type / `ImageFieldValue`'s sibling `FileFieldValue`; ES *archivo*). **"image"** stays only on image-acting surfaces — alt, dimensions, variants, `BlockImage`, the image-mode picker. The discriminator is the **§3 boundary**: *acts on an image* keeps "image"; *holds any asset* speaks media/asset/file. Enforced by `tests/media-copy-guard.test.js` and spec R31–R34 in `media-uploads.md`. |
| **Handler contract** | `(id?, Request, context?) => Promise<Response>`, isolated in tests via `ASTRO_BLOCKS_PROJECT_ROOT` + `withTempProject`. (obs #881) |
| **Bootstrap state** | A fresh instance with `users.length === 0`: the login screen is reachable unauthenticated and allows a full import/restore. Leaves bootstrap once users exist. (ADR-0015, obs #1857) |
| **Catchall** | `src/routes/api/catchall.ts` — the single precompiled REST entry injected into the consumer; dispatches `/cms/api/*` through the route table. |
| **Redirect** | An internal-only mapping from one site path to another; the target can never point off-origin. External targets are not a looser validation — they would be an explicit feature (#128). |
| **Owner** | The first bootstrapped user; owner-only gates protect user management; the sole owner cannot be demoted or deleted; `passwordHash` is never exposed. A user's **role is resolved fresh from the store on every request** — a demotion takes effect immediately, not at token expiry. (obs #878, ADR-0027) |
| **`tokenVersion`** | A per-user session generation: a positive integer. The JWT carries only `sub` + `tokenVersion`; `getAuth` reads the user fresh from the store and rejects any token whose `tokenVersion` no longer matches. The token asserts *"user X at generation N"*, the store answers *"is X still at N"*. Every record the store returns carries a valid generation — absent or malformed values read as `1` at the **store boundary** (`loadUsers`), so no consumer defaults the field. **Monotonic**, without qualification: no writer moves it backwards — a restore re-generates it above the high-water mark rather than replaying the archive's value (ADR-0028, #134). (ADR-0027, #124) |
| **Session revocation** | Bumping a user's `tokenVersion` invalidates all of their live sessions at once ("sign out everywhere"). Triggered by a **password change**, and by a **restore of the `users` unit** — which re-generates every restored record above the high-water mark of store and archive combined, signing the whole instance out (restore is treated as a security event, not a data operation: ADR-0028). Deletion and demotion need no bump (the existence check and the fresh store role cover them). (ADR-0027, ADR-0028, #124, #134) |
| **HTML sink** | A DOM property/method that parses a string as markup: `innerHTML`, `outerHTML`, `insertAdjacentHTML`. Any API-sourced value reaching a sink must be escaped by context first. (ADR-0022, #99) |
| **Canonical escaper** | The single `escapeHtml` / `escapeAttr` pair in `utils/html-escape.ts` — `escapeHtml` for text content, `escapeAttr` for attribute values. The only HTML escaper allowed anywhere. (ADR-0011, ADR-0022) |
| **i18n bridge** | The two-script pattern that feeds server-rendered i18n strings to a bundled client module: a `<script define:vars={{ xI18n }}>` that only does `window.__cmsXI18n = xI18n`, plus a `<script>` that imports `./client/x.js`. `define:vars` forces `is:inline`, so the bridge is how an admin page hands data to real (linted, escaper-reachable) module code. See `import-export.astro`. |

## 4. Conventions (how we do things here)

- **`src/` is the publish root — `dist/` is its compiled mirror.** Everything that ships lives in
  `src/` (`api`, `components`, `contract`, `img`, `meta`, `plugin`, `routes`, `styles`, `types`,
  `utils`), and each maps 1:1 onto `dist/<same-name>/` — via `tsc` for `.ts`, via a copy step in
  `scripts/build.mjs` for `.astro`/CSS/assets/manifests. Anything that does **not** ship (`scripts/`,
  `tests/`, `e2e/`, `playgrounds/`, `docs/`) stays at the repo root. So **where does a new file go?
  Ask only: does it ship?** Two traps: `tsconfig.json` must keep `rootDir: "src"` (with `rootDir: "."`
  tsc emits `dist/src/…` and breaks every `package.json` export, the `bin`, and the `__dirname`-relative
  walks in `src/plugin/index.ts` and `src/plugin/cli/init-ai.ts`); and a package-root `data/` must never exist
  — it means a test leaked a write to `process.cwd()`. See ADR-0021.
- **Skills location**: project skills are canonical under `.agents/skills/{name}/`; `.claude/skills/{name}`
  are **symlinks**. Create new skills under `.agents/` and add the symlink — never author directly under
  `.claude/skills/`. (obs #59, #63)
- **Every new feature ships a `playgrounds/basic/` sample** in the same change (also ADR-006). (obs #129 — already in DECISIONS.md)
- **Admin list pages follow one structural pattern** (`.cms-stack` → intro → optional toolbar →
  `.cms-card--no-padding` with the table *and* an inset empty-state toggled by `cms-hidden`; edit = left-column
  Pencil icon button; `<DetailModal>` not raw `<dialog>`). Diff any new admin list page against `menus.astro`. (obs #140)
- **Admin detail modals wrap fields in `<form class="cms-form cms-{entity}-detail-form">`** even when the submit
  is pure JS — the `.cms-form` ancestry is load-bearing for CSS cascade and input semantics. (obs #141)
- **All admin forms are visually aligned**: never ship a raw native `<input type="file">`; use the styled
  file-picker pattern (hidden native input + styled button + filename). (obs #1902)
- **All uploads to `/cms/api/upload` go through `uploadMedia()`** (raw-binary protocol), never `FormData`. (obs #1905)
- **Authenticated binary downloads** use the fetch + `Bearer` header + `blob()` + `createObjectURL` + programmatic
  `<a download>` + `revokeObjectURL` pattern (tokens live in sessionStorage, cannot ride an `<a href>`). (obs #1890)
- **Surface upload/admin failures to the user** — never swallow them silently. (obs #1912)
- **Release checklist bundle**: bump `package.json` (+lock) + `CHANGELOG.md` (`### Title` sub-heading) +
  `src/meta/features.json` + the **README version badge** (`README.md`, shields.io). Missing any breaks the release
  narrative. (obs #146; release automation itself is ADR-003)
- **`CHANGELOG.md` has no `[Unreleased]` section** — it is written at the release-cut commit, organized strictly by
  released version. CI-only/infra changes get no changelog entry; they fold in at the next cut. (obs #1935)
- **CI gate = tests AND `npm run check`** (`biome ci .`), which is a **separate** job from `npm test`. See ADR-0013.
- **Admin HTML rendering lives in `client/*.ts`, and every API-sourced value is escaped at the sink.**
  Never build an HTML sink from dynamic data inside a `.astro` file — `define:vars` forces `is:inline`, so
  the code cannot reach the [canonical escaper] and Biome cannot lint it (`biome.json` excludes `**/*.astro`).
  Put the logic in a client module (wired via the i18n bridge) and pass every API value through `escapeHtml`
  (text) / `escapeAttr` (attribute) before it reaches `innerHTML`. `tests/html-escape-guard.test.js` enforces
  this repo-wide; `layout.astro` is a time-boxed exception (its sinks are escaped but not yet moved — #106).
  (ADR-0022, #99)

## 5. Extending the CMS (checklist)

- **New panel screen (list + detail):** create `src/routes/admin/nombre.astro` with the table/list and a
  `DetailModal` for create/edit; inject in the plugin `injectRoute({ pattern: '/cms/nombre', entrypoint })`
  and link it from `layout.astro`. Never create separate "new"/"edit" pages — always the modal on the list
  screen. Tables: follow the unified table language in `DESIGN.md` (first column edit-only, last column
  delete-only, `font-size 0.75rem`, `window.cmsConfirm` for delete). Ref: `pages.astro`, `users.astro`.
- **New panel screen without a list (settings/cache):** `src/routes/admin/nombre.astro` without a modal
  (e.g. `settings.astro`, `cache.astro`).
- **New API endpoint:** add the function in `src/api/handlers/*.ts`; dispatch by method + segments in
  `src/routes/api/catchall.ts`; in the admin use `fetch('/cms/api/...')`.
- **Menus:** `data/menus.json` = `{ menus: [ { id, name, selector, items } ] }`; each item has `name`,
  `path` and optional `children` (nested submenus). API GET/POST `/cms/api/menus`, PUT/DELETE `/:id`.
  Selector `[a-zA-Z0-9_-]` only, unique; path required on every item (validated in client and API).
  Reordering with Sortable.js (`ghostClass: 'cms-dragging'`, handle `.cms-drag-handle`).
- **Global params:** `data/configs.json` = `{ configs: [ { id, key, value, description?, … } ] }`. API
  GET/POST `/cms/api/configs`, PUT/DELETE `/:id`. `key` unique (case-insensitive) regex
  `^[A-Za-z][A-Za-z0-9_.-]*$`; `value` string (can be empty). Public helpers `getConfig(key)` and
  `getConfigMap()`.
- **New contract prop type:** add it in `src/contract/index.ts` and `src/types/index.ts`; if there is schema-generated
  UI, support the new type in the panel.
- **Every new screen/component** reuses the design system (`DESIGN.md`): before creating classes, check
  `.cms-card`, `.cms-table`, `.cms-btn`, `.cms-field`, `.cms-badge`, `.cms-stack`, `.cms-cluster`.

**Component contract:** project components import `defineBlockSchema` from
`@astroblocks/astro-blocks/contract` and export `schema = defineBlockSchema(definition, import.meta.url)`.
The plugin config uses **only** `blocks: Schema[]` (there is no `components` option). Adding a block type =
create the component with its `schema` and add it to the `blocks` array. (See ADR-0009, `src/contract/index.ts`.)

## 6. Pre-render vs server

- Astro 6, `output: 'static'`. Routes with `export const prerender = false` are served on the server
  (require an adapter, e.g. `@astrojs/node`).
- **Every injected admin route needs `prerender = false`** — cookie-based UI i18n is invisible on
  prerendered routes under a consumer's `output:'static'` (guarded by `tests/admin-routes-prerender.test.js`).
- Server by default in alpha: `src/routes/page.astro`, `src/routes/api/catchall.ts`, `sitemap-get.ts`,
  `robots-get.ts`, `uploads-get.ts`, `src/routes/admin/menus.astro`, `src/routes/admin/users.astro`,
  `src/routes/admin/cache.astro`.

## 7. Gotchas / known traps

### Runtime artifacts (`.astro-blocks/`)
- **The filesystem is not a resolution strategy.** `.astro-blocks/` is a **gitignored build artifact**: it exists on
  your machine and is *absent* on a deployed server. Any value the **precompiled API route** needs must be **baked**
  into `vite.define` at config time. This is not a style preference — it is the same bug twice: global blocks 404'd in
  production (ADR-0009), and then block schemas did (#101, ADR-0025). If you find yourself reading `.astro-blocks/*`
  at request time, you are writing the third one.
- **Baked values are DOUBLE-encoded.** `vite.define` splices its value in as raw **source**, so
  `JSON.stringify(value)` becomes an object/array *literal* in the bundle — which every reader's
  `typeof raw === 'string'` guard then rejects, silently falling back to a default **as if the consumer had never
  configured anything**. That is what shipped the `video/mp4` 415: `allowedFileTypes` never reached the server in any
  released version. Always `JSON.stringify(JSON.stringify(value))`, and `JSON.parse` it back.
- **`runtime.mjs` cannot be imported from plain Node** — it imports the consumer's real `.astro` components. That is
  why `schema-map.mjs` exists as a pure-data twin, and why unit tests (`node --test`, no `import.meta.env`) seed the
  latter. A temp project *without* it is a **broken deployment**, and every schema-dependent handler returns 500
  (ADR-0025). Seed it, or pass `{ seedSchema: false }` deliberately.

### Localization
- **`LocalizedValueMap` fails scalar validation**: `validateBlockPropsAgainstSchema` rejects objects for
  string fields. A localized value must be **projected to a first-locale scalar before validation** (store the
  full map). `STRING_LIKE_TYPES` excludes `image`. (obs #135)
- **PUT must merge, not nest**: `mergeBlockPropsForLocale` (now in `src/utils/locale-projection.ts`) must detect an
  incoming `LocalizedValueMap` and spread-merge it, else you get `{title:{es:{en,es}}}`. `isLocalizedMapValue`
  needs **all** keys to be locale codes, and default content languages are **`es` only** — multi-locale tests must
  seed languages first. (obs #147, #143)
- **`ImageFieldValue` needs zero localization code**: its keys (`url/alt/…`) are non-locale so it passes through;
  wrap the whole object per-locale for `localizable: true`. This is the payoff of choosing an object shape. (obs #813)

### Admin UI runtime (`.astro` client scripts)
- **`define:vars` / `is:inline` scripts are NOT transpiled** — TypeScript in an inline body ships verbatim and throws
  a browser `SyntaxError` at runtime (compiles fine, never runs). Audit any `define:vars` page for TS. (obs #1855)
- **Empty `define:vars` bridge doesn't cross scripts**: `<script define:vars={{x}}></script>` then a separate
  `<script>` referencing `x` → `ReferenceError`. Put `define:vars` on the same script that consumes the var, or use
  an explicit `window.__cms*` attach. (obs #934)
- **Never render HTML from a `define:vars`/`is:inline` script** — beyond being un-transpiled and un-lintable, it
  cannot import the [canonical escaper], so any `innerHTML` built there is an unescaped XSS sink. This is exactly
  how #99 happened. Move rendering to a `client/*.ts` module and feed it via the [i18n bridge]. (ADR-0022)
- **Block-form fields do not re-render on value change** — react to changes with **in-place DOM mutation**, not a
  global re-render. Also, `<img>` `error` events **don't bubble** → use capture-phase delegation. (obs #806)
- **`.cms-input` is a text-input style — never on checkboxes/radios** (it adds padding/border the checkbox reset
  doesn't clear). Canonical boolean field: `.cms-field.cms-field-checkbox` with no `cms-input`. (obs #142)
- **`GlobalBlock` locale on render**: `Astro.currentLocale` depends on the consumer configuring Astro i18n, but
  astro-blocks uses its own prefix routing — resolve locale from the URL, don't trust `Astro.currentLocale`. (obs #144)

### i18n / SSR rendering
- **Every injected admin route needs `export const prerender = false;`** — cookie-based UI i18n is invisible on
  prerendered routes under a consumer's `output:'static'`. Guarded by `tests/admin-routes-prerender.test.js`. (obs #933)
- Note: fixes to `.astro` client/SSR behavior only surface in a **real browser against a rebuilt dist** — the
  node:test suite cannot catch them (hence the e2e/Playwright smoke coverage). (obs #933, #934)

### HTTP / upload protocol
- **Bodyless `POST`/`DELETE` to `/cms/api/*` must send a non-form `Content-Type`** (e.g. `application/json`), or
  Astro's origin-check middleware 403s them behind reverse proxies. (obs #1904)
- **`/cms/api/upload` accepts only the raw-binary protocol** (`request.arrayBuffer()` + real MIME `Content-Type` +
  percent-encoded `x-cms-filename`). `FormData`/multipart is rejected. Always use `uploadMedia()`. (obs #1905)
- **Upload security**: the on-disk extension must be derived from the **validated MIME**, not the user filename
  (an SVG-as-`.jpg` bypasses extension guards → stored XSS). Path-containment checks must include the separator
  (`startsWith(dir + path.sep)`) to avoid sibling-dir bypass. (obs #800, folded into ADR-0018)
- **`vite.define` splices its value in as SOURCE, so JSON bridges must be DOUBLE-encoded.**
  `JSON.stringify(array)` emits an array *literal* into the bundle; the runtime readers all guard with
  `typeof raw === 'string'` before `JSON.parse`, so a single-encoded bridge does not fail loudly — it
  **silently falls back to the default**. `allowedFileTypes` shipped that way and never reached the server in
  any released version, which is what actually caused the reported `video/mp4` 415. Assert the *round trip*
  (`runtimeValueOf()` in `tests/plugin-resolve-options.test.js`), never the define value on its own: a plain
  `JSON.parse` of it yields the array under **both** encodings, which is why the tests missed it. (ADR-0023)
- **Uploads are authorised before the body is read.** The MIME comes from the `Content-Type` header, so the
  denylist, allowlist and size check all run on headers alone. Images are buffered (sharp/`imageSize` need
  them); video, audio and documents **stream to disk**. Every early exit from the streaming path must `unlink`
  the partial file — a leaked partial upload is the failure mode of a streaming ingest. (ADR-0024)
- **`/uploads/*` speaks HTTP Range, and must.** Safari requests the first two bytes of a media source and, with
  no `206` + `Content-Range`, **discards the source and plays nothing**. The route also streams from disk: it is
  public and unauthenticated, so `fs.readFile()` on a 100 MB video was memory per viewer. (ADR-0024)

### Data store & testing
- **Concurrent writes corrupt the JSON store** — always go through `writeJson` (atomic) + `withFileLock`. (ADR-0008, obs #805)
- **Fire-and-forget async in handlers can outlive the test's env scope**: `handleUpload`/`handleReplaceUpload`
  spawn variant generation un-awaited via `spawnVariantGeneration`, which resolves the store path *at write time* —
  a job that outlives the test writes to `process.cwd()/data` once `withTempProject` has unset
  `ASTRO_BLOCKS_PROJECT_ROOT`. Tests that upload/replace **must `await drainVariantJobs()`** (from
  `utils/variant-generator`) in `withTempProject`'s `finally`, *before* the env restore + temp-dir removal.
  `scripts/check-root-data-leak.mjs` (chained in `npm test`) fails the suite if a package-root `data/` ever
  appears — a `.gitignore` rule is not self-enforcing. (obs #836, #96)
- **Delete/status-code inconsistency across domains**: `handleDeleteMenu` → `204`; `handleDeleteLanguage` → `200`
  with a JSON body. Don't assume a uniform delete contract. (obs #879)

### fflate (import/export zip)
- **Use fflate's synchronous `Zip`/`Unzip` in Node**, not `AsyncZipDeflate`/`AsyncUnzipInflate` — the async worker
  variants fail with "u8 is not defined" under ESM and hang instead of throwing. (obs #1877)
- **`file.ondata` fires incrementally even on a single `unzip.push(buffer, true)`**, so cumulative-byte
  zip-bomb ceilings work without a streaming pump. (obs #1883)

### Tooling / CI / release
- **`biome ci` treats an unformatted NEW file as an error (exit 1)** even when tests + `tsc` pass. Fix with
  `biome format --write <file>` (NOT `biome check --write`, which applies lint autofixes). Never trust a
  sub-agent's lint self-report — re-run `npm run check` and check the exit code. (ADR-0013, obs #1978, #2004)
- **Stacked/feature-branch PRs on GitHub**: do NOT `--delete-branch` a middle PR of a chain — deleting a base
  branch **closes** the dependent PR (unrecoverable). Merge in order, retarget/rebase the next branch onto main,
  force-push to trigger CI (which only runs on `base: main`). Delete branches only at the end. (obs #1959, #1853)
- **`npm version` screenshot hook is flaky** (Chromium cold-start > 180s) and can abort after the version bump
  but before the release commit/tag — re-run screenshots, then commit/tag manually to match `package.json`. (obs #1853)
- **Never `npm audit fix --force`** — it downgrades astro to 2.4.5. The accepted esbuild advisories are dev/build-only
  and not in shipped `dist/`. (referenced by dependency-sweep memory)
